原文是飞书文档《AI 算命，到底在算什么？》，作者 Jing（即刻 ID：JoJoJoJoJoJoJo 系）自述为"多年互联网从业人员，玄学爱好者"，独立开发维护了一年多的算命类 GPTs（Chinese Bazi Fortune Teller）积累了 10W+ 用户，长期保持在 GPT Store 首页榜单。这篇长文（文档最后修改于 2024 年 12 月）就是他这一年观察、体验和思考的整理。笔记性质说明：以下是对原文的梳理重组 + 我的分析，引号内为原文摘录，完整内容建议读原文。

这篇笔记表面聊玄学，实际上是一份"垂直知识领域 × LLM"的工程方法论复盘——把一个千年行业的问题拆到可以动手开发的粒度。先说我的总体结论：

> 算命的本质不是预测未来，而是提供心理立足点；这个行业的第一性问题是"建立信任"。AI 算命做得好不好，关键不在模型多强，而在"传统确定性算法 + 结构化命理知识 + RAG + 多 Agent"这套工程组合拳打得好不好。

## 算命在算什么：70% 准确率悖论

命理界前辈梁湘润说过，算命的准确率通常只有 70%。那么问题来了：在不能保证 100% 准确的情况下，为什么大家还会想去算？作者给的回答是整篇文章的地基——算命提供的从来不是"预测"，而是心理和情绪层面的指引。

找过"大师"的人多半经历过这种场景：你隐隐感觉大师在顺着你的话往下说，夹杂着模棱两可的推测和好听的祝愿，但你偏偏觉得"有道理"。说的是好事你会信，说得不好你也愿意为"化解之法"买单。那为什么不直接去看心理医生？作者的区别分析很精彩：心理医生用理性分析帮你解开心结，但"冷冰冰"的建议缺少一种与自我相关的深度连接；命理则通过神秘的符号语言解读你的过去和未来，让你感受到"命运的独特性"，相信"自己的存在意义深远，人生的每一步都可以被解释甚至规划"。

> 算命并不是在解决生活的问题，而是通过神秘的语言，赋予你面对生活的勇气和信念。

这个判断直接决定了 AI 算命产品的验收标准：不需要 100% 准确，需要的是足够好的心理体验。

## 第一性问题：建立信任

信任感是算命内容被接受的唯一前提。作者的"陌生人思想实验"：如果一个陌生人突然告诉你"明天会发大财"，多数人不会信，反而陷入精神内耗（"他看着就不起眼，肯定是胡扯""他不会是在变相咒我吧"）。而如果这个人能准确说出时间、地点、事件，甚至长相就是"大师的样子"，信任感瞬间建立，后面的内容便水到渠成。

传统命理领域建立信任的三种方式，值得逐条品味，因为它们后面会被逐条映射成产品能力：

| 方式 | 机制 | 心理学依据 |
| --- | --- | --- |
| 口碑相传 | 熟人推荐的大师天然更靠谱 | 信任感来自人际关系的延伸 |
| 知识外显 | "用专业说话"，五行旺衰、阴阳生克的理论能自圆其说 | 逻辑自洽性带来专业感 |
| 沟通同频 | "察言观色"，从面相手相谈吐判断对方，句句说到点子上 | "他真的懂我"的被理解感 |

作者强调：缺乏信任感时，无论内容多准确，用户都会觉得是"胡说八道"；信任建立后，算命就"不再是冷冰冰的理论输出，而是一场深入心灵的对话"。

## 把算命翻译成一条数据流水线

文章最有工程味的部分：把算命流程从数据和软件视角拆成六步。这个拆法让"哪里已经数字化、哪里卡住了"一目了然——

| 步骤 | 大师在做什么 | 数据视角 | 软件视角 | 数字化程度 |
| --- | --- | --- | --- | --- |
| ① 样本构建 | 咨询出生年月日、地点，观察面相手相，或按流程抽牌取象 | 采集结构化/非结构化用户数据 | 表单输入 | ✅ 成熟 |
| ② 特征提取 | 八字排盘算天干地支、五行十神；塔罗确认牌阵牌面 | 固定算法提取关键特征 | 固定算法计算 | ✅ 成熟 |
| ③ 数据检索 | 凭记忆和经验翻找关联知识（如八字金多就去查从革格、金白水清） | 从知识库检索关联数据 | 知识检索 | ❌ 卡住 |
| ④ 数据分析 | 结合格局、强弱、十神、旺衰推演结论（流派差异最大的一步） | 知识模型推理 | 复杂模型分析 | ❌ 卡住 |
| ⑤ 输出结果 | "铁口直断"或委婉陈述，因人而异 | 归纳总结成报告 | 结果呈现 | ⚠️ 模板化 |
| ⑥ 动态调整 | 按客户反馈（"很准"/"不准"）调整输入输出 | 反馈回流优化模型 | 参数调整 | ❌ 缺失 |

前两步是确定性计算，从计算机软件兴起之时就有实践——作者贴了上世纪的星盘软件截图，核心功能和现在的排盘 App 没有区别。真正卡住行业三十年的，是后四步。

## 传统命理软件为什么替代不了大师

### 算不准：知识与规则的双重困境

第一步困境是**缺乏高质量的命理知识数据**。命理知识主要来源于《三命通会》《滴天髓》这类古籍，成书时间跨度大、表述不统一——同一个十神"七杀"，有的书写"偏官"，有的写"煞"或"七煞"，检索出来的是"若七煞止一，而制伏有二三处，喜行煞旺地……"这种高度依赖命理师经验判断的古文。软件高度依赖结构化数据，而古籍全是叙述性文字。作者举了"子午双包"格局的例子：书里说"人命或两子两午，或两午包一子，或两子包一午……遇者主贵"，要程序化只有两条路——穷举法硬编码所有柱位组合，或写函数算法推导，无论哪条都是大量人工标注和编码工作。

第二步困境是**命理规则数量庞大且模糊**。仅十神定位就有数百种解读，再叠加柱间关系、刑冲合会等维度，规则组合指数级增长；更麻烦的是规则本身靠口口相传，历史传播中丢失了大量上下文——比如"身强""身弱"的判断标准，各流派定义完全不同（有的只看月令，有的要算复杂的生克旺衰），程序实现根本"不知道以谁为准"。

### 没人情味：模板化与单向输出

传统命理软件输出的是预设模板生成的固定报告，用户觉得"套话"太多；交互是"输入数据 → 输出报告"的单向流程，用户对结论有疑问时无从追问，软件也感知不到用户的焦虑和迷茫。对照前面"信任感三件套"：口碑相传、知识外显、沟通同频，传统软件一样都不占。

### 两条产品路线都到顶了

行业给出的两条路各有天花板：**专业工具型**（给大师用的排盘工具，类似医院问诊系统）多年没有颠覆性创新，停留在"自动计算基础特征"；**咨询平台型**（连接大师和用户的获客平台）则两头为难——放任管理则服务质量没保障，深度介入标准化又会削弱用户与大师的情感连接，"使服务体验的温度与个性化大打折扣"。作者由此引出全文题眼：是时候寻找下一代的命理软件了。

## AI 的机会：两个方向与一个 X Factor

### 方向一：基于海量用户数据的生成式模型

八字有上百万种组合，从数据量看训练一个模型并非遥不可及，但核心问题是数据收集：既需要大量准确的出生日期时间，更需要"人生轨迹"的多维度标签数据——以八字断学历为例，需要一批人的真实高考录取数据，而这些数据掌握在公共机构和大企业手里，不可能轻易授权。作者提到 2023 年底的热门论文《Using sequences of life-events to predict human lives》（life2vec，用生命事件序列预测人生）是从统计学和深度学习角度做的类似探索；如果认可玄学的统计学意义，时间序列模型与八字流年、大运的推演逻辑有天然契合点。结论：这条路不是无解，而是对数据与技术要求太高，个人和小团队玩不起。

### 方向二：用 LLM 优化传统技法和数据推理

这是个人和小团队能操作的方向，核心是"通过 LLM 的推理能力，将已有的命理知识和规则进行整合与重塑"，有三个可以尝试的领域：

- **命理规则结构化**：用 LLM 把五行生克、刑冲合会、十神关系等经典理论转化为可计算的结构化规则库（比如"身弱喜印、忌财"→ 机器可读的规则）——颠覆了过去完全靠人工归纳总结的过程；
- **生成式推理**：LLM 能基于十神组合和流年关系逐步推导（从"身弱"推到"喜印"再结合大运推事业运），用思维链输出可解释的推理过程，而且"人工大师不可能记得每个客户咨询过的内容，但是 AI 可以"；
- **个性化与情感化表达**：按用户偏好的语言风格和情绪状态调整解读——这正是传统软件最缺的"人情味"。

至于 X Factor（AGI），作者的想象是"超脑级别的数据整合能力"：命理推演与职业、财务、健康数据深度融合，AI 从预测工具变成"真正懂你的伴侣"。这部分当展望看即可。

## 当前 AI 落地的六板斧

这是全文最干的部分——围绕方向二，作者给出六条可操作的实践。

### 1. 基础信息必须准确：排盘交给传统算法

GPT 刚上线时直接问八字，"最基本的排盘都是错的"——生成式模型在数理运算和规则推理上有短板，强规则计算不能指望 LLM。正解是用 function call 让 AI 在合适的时机调用传统排盘接口（作者展示了 Coze 的 API Plugin 配置）。一个扎心的实测数据：他对比过约 10 家模型，能做到参数识别和生成基本不出错（10 次里对 8 次以上）的寥寥无几。

### 2. 结构化知识数据：LLM 重塑命理的核心

直接把算命书丢给 GPT 效果很差，两个原因：一是 AI 并不真的"理解"古书——即使上了 RAG，问"我什么时候发财"，从古书里召回的也是"时至发财发福，运来顺水行舟"这种虚无缥缈的内容，而 LLM 最好的输入是 `"大运.天干 == 财星" -> "发财"` 这样的结构清晰规则；二是输入输出表达差异大——古书说"某星入命，利于仕途显达"，用户想听"今年事业顺利，有望升职加薪"。

对应的两个流水线：**关键规则结构化**——把书籍扫描摘录喂给 AI，用"帮我解析并生成 JSON 返回"的 prompt 批量转成结构化规则数据，把过去高成本的人工标注变成自动化流水线；**数据描述改写**——用带示例的 prompt 把古文改写成通俗表述。作者用 Transformer 注意力机制解释了为什么改写有效：前文越贴近目标答案，注意力分布越精准。比如"偏财财位发他乡，慷慨风流性要强……"这句断语，改写成"偏财旺的人通常事业发展多在异地，性格慷慨大方，热爱社交……"再喂给 LLM，效果就好很多。

### 3. 合理注入知识库（RAG）

命理场景 RAG 的三个特别注意点：

- **按用户意图选库**：事业、婚姻、财富各建知识库，每次交互不必全量注入（token 也不允许），意图识别用 4o-mini 这个量级的小模型就足够好；
- **结构化注入**：直接问 GPT"戊辰 壬戌 辛酉 庚子 这个八字的时干十神是什么"，答案基本是错的（作者实测"很接近了，不过结果还是错的"）；要预先注入结构化的四柱信息：

```json
{
  "时": {
    "天干": "庚",
    "天干十神": "劫财",
    "地支": "子",
    "地支藏干": ["癸"],
    "地支十神": ["食神"]
  }
}
```

  这之后再问十神相关的推理就不会错了——别让 LLM 去算它能查表得到的东西。

- **内容验证**：用相似度算法校验生成内容与检索文档的一致性来抑制幻觉，不一定需要 LLM；但验证会拉长用户等待时间，非关键问题可以不验。

### 4. 多 Agent 协同

至少三个 Agent 分工：**意图判断 Agent**（解析输入意图，转成结构化任务指令）、**知识生成 Agent**（结合 RAG 检索知识、动态获取上下文如当前时间）、**内容输出 Agent**（负责对用户说话，组织符合语境的输出）。推理不必一蹴而就，可以分阶段优化。

### 5. Prompt 调整

几条实战技巧：用统一的框架（推荐 CO-STAR，"很符合设定命理师的工作流程"）；基础知识在 Prompt 里高亮设定（五行生克是 AI 最容易错的地方）；推理用思维链（作者当时评价 o1 模型"太慢了，比较难产品化"——2026 年回看，这条已经过时，推理模型的延迟和成本这一年降了一个量级）；**选择题优于填空题**——给 AI 明确的选项比让它自由生成判断准确率高得多；**专注一个流派**——知识不是越多越好，是越专注越好。

### 6. 传统算法的精益求精

别把目光全放在 AI 上：身强身弱的判定若选定一种成熟流派的规则（量化日主得令、得地、得助的权重），完全可以程序化实现，既减少 AI 推理依赖又省算力。极致的方向是完全数学量化（作者引用了《量化五行力》的研究），但这里有个漂亮的自我反问："假如量化算出的结果，与用户的现实情况不符，是否还有空间保留这份信任感？"——绕回了全文的信任主题。

## 作者的实践：从 GPTs 到独立产品

Chinese Bazi Fortune Teller 这个 GPTs 起于业余爱好，无推广情况下用户持续增长，作者持续更新一年（主要是知识库），保持在 GPT Store 首页榜单。最意外的发现是"东方命理文化在 GPT 的载体上，很容易就得到其他国家的认可"——他收到过葡萄牙语、俄语、阿拉伯语用户的正面反馈。

但 GPTs 的产品交互限制和模型黑盒让上文很多优化逻辑难以落地，所以他正在重构独立的 AI 算命产品（cantian.ai），可以灵活控制输入的知识和变量。最大的挑战依然是命理知识结构化——"GPT 出现前，我不敢想"，现在有 AI 辅助开发，个人加上社区和专业人士的力量，这事才做得动。

他的目标定位也值得注意：**不是替代线下大师**（"人与人沟通带来的情感慰藉，是 AI 在短期内很难替代的"），而是让 AI 通过详实的知识推理和匹配的沟通方式（文字、语音、甚至 VR）提供足够的信任感，"成为用户某种形式的精神伴侣，让用户在迷茫时能够快速找到精神落脚处"。

## 我的几点分析

1. **这是一份可迁移的"垂直知识领域 × LLM"方法论模板。** 把"命理"替换成中医、法律咨询、风水、税务，整篇文章的框架几乎原样成立：确定性计算交给传统算法（排盘 → 法条检索、方剂配伍），领域知识做结构化 + 现代表达改写，交互层用 RAG + 多 Agent。卡点也高度相似——古籍/行话无结构、流派/判例互相矛盾、优质数据被垄断。任何做垂直领域 AI 应用的人都能直接抄作业。

2. **"信任感"框架对 AI 产品普遍适用。** 作者实际上把一个 2024 年的 AI 产品问题，还原成了一个千年行业早已解决过的问题：AI 产品建立信任同样靠三件套——口碑（用户案例与推荐）、知识外显（思维链让推理过程可见）、沟通同频（长期记忆 + 个性化）。反过来说，产品里的幻觉和错误之所以致命，不是因为不常见，而是因为它摧毁的是信任而不是准确率。

3. **"结构化注入"是短期性价比最高的 pattern。** 十神那个例子本质是一句通用原则：LLM 不该计算它能查表得到的东西。这与当下 Agent 工程里"确定性工具调用 + LLM 推理"的组合思路完全同构，也和 RAG 演进中"把检索结果结构化后再喂给模型"的最佳实践一致。文中"选择题优于填空题"就是约束输出空间的朴素表述。

4. **时间戳值得注意：这是 2024 年 12 月的实践。** 作者吐槽 o1 太慢难以产品化、靠 CoT prompt 补推理、用小模型做意图路由——这些 workaround 在 2026 年的推理模型面前大半已被原生能力覆盖。但文中真正不过时的判断是：瓶颈不在模型，在知识的结构化（他的主要精力一年到头都在更新知识库而非换模型）。这和当下 Agent 领域"上下文工程 > 模型选择"的共识相互印证。

5. **伦理层面是这篇文章的留白。** 文章开头自己就吐槽了行业乱象（"内容鸡肋，产品劣质，付费不断"），而"算命不需要 100% 准确、提供的是精神能量指引"这个产品哲学，天然游走在情绪价值与情绪操纵的边界上。玄学场景对幻觉宽容，换成医疗、法律场景同样的方法论就必须配上严格的事实校验——"内容验证"那一板斧在不同领域的权重完全不同。此外，情感依赖型产品的成瘾性与付费设计，原文没有展开，做这类产品时这是绕不开的自问。
