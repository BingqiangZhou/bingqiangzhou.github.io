上一篇拆 [video-shotcraft](/posts/video-shotcraft-skill-deep-dive/) 时留了个尾巴：作者同月发的系列第二作 **video-talkcraft**（口播视频版），「本文不展开」。这篇就是补上的展开。一句话定位：**把 Claude Code / Codex 变成口播视频动效工作室**——你给它一份口播稿和一条成品配音，它在本地把配音对齐成**字级时间戳**，把每个语义拍写进 SHOTBOOK 分镜，然后用 Remotion 渲出解说成片：动态字卡、证据截图、运镜、素排字幕、音效，全部锁在人声上。

「口播视频」和 shotcraft 做的「产品宣传片」听起来只差一个题材，但整个技术重心因此完全换了：宣传片的时间骨架是**音乐 BPM 网格**（librosa 分析、拍号写时间线）；口播视频的时间骨架是**人声**——动效必须在「这个词被说出口的那一刻」发生。于是这个 skill 的第一块基石不是任何动效，而是一条**本机 CPU 的字级时间戳管线**，后面的一切（分镜、验收、lint）都挂在这条管线上。这篇笔记是我把 SKILL.md、八份方法论文档、卡片索引、抽样配方卡、11 个脚本和画廊基建全部读完之后的结构化总结，克隆分析基于 2026-09-01 主干 `d2e1db9`。

> **TL;DR**：video-talkcraft 在 shotcraft 的「经验沉淀系统」之上又加了一层东西——**把判断题变成测量题**。节拍时刻不许手敲秒数，必须从时间戳文件查询，机器闸校验误差；标注坐标不许目测，必须 DOM 实测；卡片实现不许凭理解重写，必须复制源码且过相似度 lint；音效「在场」不许信相对底噪，必须过绝对阈值。「看起来对了」在这个 skill 里不是验收结论，每个曾经骗过静帧 QA 的缺陷，都变成了一条带定版日期的机器规则。对写 agent skill 的人来说，这套「给 agent 的自欺行为逐个上闸」的打法，比 78 张卡本身更值得抄。

## 一、它是什么：六次提交里的十天

两个和上作不同的姿态先记下：一是**许可**换成了 PolyForm Noncommercial 1.0.0——个人、教育、研究免费，用它做出来的视频归创作者，但工具本身的商业使用需作者授权；二是**边界更克制**——SKILL.md 开头就写死「TTS 合成与数字人生成技术不在本 skill 内」，配音和人物素材是输入。skill 只管合成侧，这个边界让它不必纠缠于「生成质量」这种深水区。

## 二、核心工程：把人声变成全片时间锚

`scripts/timestamps_cpu.py` 是整个 skill 的地基，值得单独讲。它做的事：给一条成品配音（wav/mp3）和逐字一致的口播稿，输出每个字/词的起止时刻。技术路线是 **ASR 词级时间戳 + 与口播稿做字符级序列对齐**，对齐的匹配键设计暴露了作者对中文的真正理解：

- **CJK 是可靠锚点**：ASR 转写出来的汉字经常是同音字错写、随机吐繁体，所以匹配键 = 繁简归一 + 无声调拼音——同音字不算错。反过来拉丁词各家 ASR 都常拼错，不做锚点，只在相邻汉字锚点之间线性插值；
- **数字一律写汉字**：口播稿里「197747」无法与「十九万七千」的读音对位，这是硬规则；
- **逐句质检**：每句输出 CJK 锚点覆盖率 match，低于 0.90 标记 `ok=false`，人工听那一句。

四配置横评（110 秒中英混合口播，对照 GPU 强制对齐器真值，n=472）写死在脚本头注释里：**FireRedASR2-CTC int8**（默认，767MB 模型手动下一次）字级最大偏差 200ms（30fps 下 6 帧）、零误报、24 秒跑完；faster-whisper small 中位数 20ms 最好但尾部 413ms 且 2 句边缘误报；Qwen3-ASR+Aligner p95 60ms 分布最优但要 5GB 体积加 torch。选型判词很清醒：「30fps 一帧 33ms，中位差异无感，**尾部才是风险**（动效挂错字）」。连「whisper 不要传 initial_prompt，喂口播稿进 prompt 会让前几段整段幻觉错位」这种坑都记着。

更漂亮的是开放性：输出 schema 就四个字段（`sr/total/sentences/words`），SKILL.md 明说「满足此 schema 的任何对齐工具都可替换」。时间戳管线没有焊死在某个模型上，它定义的是**接口**。

然后是这条管线最深的引申：**字幕句边界 = 全片时间锚点**。`make_timing.py` 把时间戳转成 timing.json，实现层用 `tSay/msSay/atChar()` 查询任意字的时刻。核心范式一句话：「解说词驱动画面，每句都要有活的画面响应，但**新元素只在语义拍边界进场，禁止机械的一句一个新元素**（一句一元素是堆积型凌乱的制度根源）；一个节拍只有一个主角，说完就让位」。口播稿本身也有写作纪律：每句一个信息点、钩子在第一句（数字/冲突）、13 句约 95 秒、先调研核实事实列「事实红线清单」。

## 三、反 PPT：七层模型与四套全局系统

`cinematography.md` 开篇把「PPT 感」诊断为四个结构性病根，而不是风格问题：**没有相机层**（画布静止，元素只是在固定舞台上淡入滑入）；**元素入场后就死了**（动画全是 entrance，到位即冻结——这正是 PPT「进入效果」的模型）；**场景之间硬切翻页**；**文档版式 + 信息堆积**（标题左上、要点网格、元素只进不出）。解药是一套七层镜头模型（相机/焦点/主体/附着效果/配角/环境/遮罩）加层预算：英雄时刻 4–6 层活跃，过渡镜头 2–3 层，**任何镜头不允许只有 1 层**——至少留相机微漂和环境呼吸。

七层是词汇表，落到代码是四套全局系统（`template/motion-systems/`，全部确定性、零 Math.random、seek-safe——和 [HyperFrames](/posts/hyperframes-skills-deep-dive/) 的核心契约同一条）：

1. **G1 CameraRig**：每场景一条全程连续的相机曲线（scale/x/y/rot 独立稀疏关键帧，inOutSine），重音词叠加 3–6 帧冲击脉冲——**加法叠加、永不重置慢曲线**。相机路径集中在 shots.ts 一张表里，每条写导演意图注释；
2. **G2 视差平面**：背景 0.5 / 主内容 1.0 / 前景 1.2，「背景永远进视差层，不做静态贴图」；
3. **G3 Idle + 让位状态机**：元素生命周期 forming → resolved → handing-off → gone 全是帧的纯函数；resolved 期必须有微动（双不可通约频率正弦，seed 错开相位）；新主体入场帧前 6 帧，旧主体开始让位——声明式地把下一主体的 ASR 锚点直接传给上一主体的 `retireAt`。让位有三种方式，按「这元素还回不回来」选：真退场/降权留守/相机离开即让位，且降权留守的元素**计入**同屏预算；
4. **G4 环境常活层**：呼吸 vignette（8s 周期）+ 斜向扫光 + 分幕色温（幕边界 1.2s cross-fade，「让变化被感到而不是被看到」）+ 重音三段曝光脉冲。四张事件表是每片配置，不是库代码。

转场是「运动承接」哲学：每个镜头边界必须有明确处置、**禁止裸切**——六式转场（推穿/过曝翻页/whip-pan/黑震切/后拉冷却/粒子溶接）共享 lead/tail 重叠 12–16 帧的机制，ShotFade 只做像素淡化，运动由两侧相机曲线**同向承接**（「方向断裂比硬切更糟」）。黑震切全片只许一次留给最大反转；「一个边界只用一式，100 秒的片 5–7 个边界，重复用同式比六式全上更有风格连贯性」。还有一条替代范式：**长镜头世界画布**（longtake.tsx）——多镜头是剪辑思维，长镜头是空间思维，内容钉在世界坐标上，一台相机连续运镜过去，「空间连续性本身就是转场」。

这一层的工程铁律密度是全库最高的，随手几条感受一下：相机曲线**末键必须落在片尾之外**（正好压在片尾会让最后 0.9 秒慢到停死，静止检测照样报 FAIL）；`Infinity` 不能进 interpolate 的 inputRange（Remotion 直接抛硬错误，哨兵用 `1e6`）；场景代码里**绝对秒只许出现在具名 props 上**（`at=`/`retireAt=`），写进函数实参的字面量是批量改期时最容易漏的一批——实测 31 处漏改直接产出 P0；细密纹理禁入相机缩放层（特征不大于 2px 的点阵在连续缩放下亚像素爬行，整块读作画面在抖）；三种时间基（绝对秒/shot-local/Sequence-local）必须经同一个 time.ts 换算，「别各算各的」。

## 四、SHOTBOOK：分镜不是镜头列表，是层矩阵

实现前必须产出的 SHOTBOOK 是这个 skill 的分镜格式，我认为是它对「怎么给口播做分镜」这个问题最有原创性的回答。设计流程分两步：先用**三面分层工作单**（背景面/主体面/文字面——每面回答一个问题的粗颗粒工作单，背景面永不缺席，写不出动效就写「继承全局系统」但不许写「无」）定骨架，再展开成**逐节拍层矩阵**。矩阵长这样（shotbook-example.md 的真实范例节选）：

| 节拍 | Layer | 对象 | 动作 | 角色 |
| --- | --- | --- | --- | --- |
| 36.08 卡在指数 | L3' | 0.5991 大数字 | 中心浮现；球群亮度降 25% | 数字接任主体，环境让能量 |
| 41.52 零点六零四四 | L3'' | 0.6044 | 旧数字划线击落、新数字同帧 punch 入 | 单帧替换=英雄时刻 |

注意节拍列：**锚字 + 绝对秒**，时间全部来自时间戳文件；每行的动作必须答得出「它在配合谁」，答不上来就删。配套还有七种镜头类型预设（钩子/论证/数据/证据/金句/收尾/B-roll）直接抄再改，每种给三面默认分配。

比格式更重要的是 2026-08-28 定版的**排版预算**——「凌乱的克星」。起因是一次实战复盘：用户判「凌乱」的两个镜头，都不是单个动效错了，而是排版没有预算。八条规则逐镜核：

- 分镜按语义段落切，禁止机械一句一镜；每镜只许一个 primary visual job（钩子/定义/数据/流程/对比/结论/CTA 之一）；
- **枢轴句归下一镜**：「但这次不是 X」式转折是下一镜的第一拍，切镜点提前到枢轴句起点，旧镜先清场，「开题动效上干净的舞台，不叠在旧话题的满画面上」；
- 同屏主体组不大于 3（降权留守计入），第 4 组进场前必须有一组真退场；
- 每镜全程保留至少一个空象限——「四角加中带全占的环形满盘 = 画心空洞、视线无路径，判凌乱」；
- hero 造型一屏一个（三个数字三种 hero 造型互相抢戏是实测反例）；
- 画面文字是至多 12 字的提炼，与字幕整句重复 = 同一信息双份同屏；
- 布局级变化每分钟 2–4 次，「切换是标点不是节拍器」；
- **错峰三段序**：旧面板完全退场 → 人物换位/新主体入场 → 新面板才淡入，三者不得交叠。

这套东西的本质是把「画面看着乱」这个纯主观判断，拆成了分镜阶段就能逐条核对的预算表——又是「把判断题变成测量题」。

## 五、78 张卡：保真铁律与「动效范围」

卡片体系沿用了 shotcraft 的判例式写法（frontmatter 六字段 + 意图/动效核心/参数表/已知坑/复用指引，每条坑写「为什么一眼假」），但有两处重要的新增。

**第一处是 tsx 成为正主。** 2026-08-28 起，每张卡配一份单文件自包含的 Remotion 源码（只 import react 和 remotion，CONFIG 常量顶置），skill 的实现方式就是「复制进工程改 CONFIG」。这不是便利性优化，是对一次重大翻车的结构性回应：**只读 md 文档就凭卡名手写「神似」简化版，是已发生过的最大翻车**——回弹/拍击/密度全丢、取景框括号方向画反、名片变色块。所以有了 `card_lint.py`：工程里用到的每张卡必须真实存在 `src/cards/<slug>.tsx`，且与模板的归一化文本相似度不低于 0.55（改 CONFIG 和文案在容忍内，从零重写过不了）。设计洞察很直白：**「复制」比「理解后重写」既便宜又保真——skill 设计要让正确路径成为最省力的路径**。

**第二处是每张卡必填的「动效范围」节**：属于本卡的（动效本体清单）/不属于本卡的（占位物、示例文案、具体配色）/迁移接口（换风格换尺寸改哪些参数）/底色要求。这是复用契约——复用者据此知道拿走什么、丢掉什么。比如 host-shrink-to-chip 卡（人物缩位让台：讲者从全屏 0.42 秒缩进角落圆形头像章继续口播，图形从对侧错峰 0.15 秒接位）明确写：缩位时序和「角标里的人必须还在动」属于本卡，chip 落左下还是右下不属于（但「必须是下角」是硬约束不是可迁移项），几何全部是比例、换画幅不用改代码。

另一个有意思的定版是**产品界面卡的例外**：demo 视觉基准整体是「白舞台中性化」（零装饰、黑字灰辅、动效语义必需的颜色才保留），但演真实产品界面的卡——chat-gpt、claude-code、x-follow-card——**必须完全还原产品样式**，「目标是截图放在真产品旁边分不出来」。理由写得很透：这类卡里**产品皮就是内容本身**，灰阶化之后 chat-gpt 退成「某个聊天框」，它那五条界面语法特征（单行药丸、建议 chips、问候语占中、圆到圆 morph、点睛色在语音端）全部读不出来，卡的存在理由就没了。

卡片之间还织了一张选型决策网，几乎每张卡都写清与相邻卡的分界：number-counter（过程）与 number-slab-pop（结论）与 metric-with-sparkline（数加趋势）三分数据镜头；media-pop-in「歪着叠」、motion-blur-slam-in「同向怼」、gooey-morph「并列拼」三种素材入场不混用；glass-code-walk（1.5–1.8 倍逐行走读）与 cursor-locked-zoom（2.6–2.8 倍锁光标跟拍）共享同一套反解公式但档位不同。「界面剧场」子类（终端逐行、聊天自演、编码智能体终端）还有四条共有纪律，核心是**时间只从一处进入**：一张时刻表是唯一时间源，光标、控件、结果都是它的函数，「这是能排到三拍以上还不散架的全部原因」；以及**换态是硬切不是动画**——给状态变化配过渡就变成「样式在做动画」，观众读不出是哪一下触发的。

## 六、证据与人物：口播视频的两个独有子系统

口播/解说内容天然是「关于事实的」，所以这个 skill 有两套 shotcraft 没有的子系统。

**证据系统**的核心是 2026-08-30 定版的「真图硬规」：话题存在可截的真实页面（产品官网/GitHub/文档）时，成片中的浏览器/页面类镜头**禁止用代码 mock 冒充截图**——卡片 demo 里的灰条假 UI 是占位物，成片必须整块换成真图；mock 只允许表现无真实对应物的示意 UI，且 SHOTBOOK 逐镜标注「为何无真图」。引申规则同样锋利：口播讲「这样的成片」时示例画面必须是真成片片段；讲长页面时用 Playwright 全页长截图；**真图上的标注坐标一律机器实测、禁目测**——「目测偏 30px 曾把停靠环框到标题下方的缩略图上，返工两轮」；会滚动的真图，标注必须钉在内容坐标系上随内容动。配套还有调研记账：承载关键事实的来源页逐一截图存档，sources.md 里链接与本地截图一一对应，「禁止只存链接不留证据」。B-roll 走 Pexels + Pixabay 双源并行，只收免署名源，连「Videvo/Mazwai 已死、Mixkit 双轨授权坑、Coverr 免费档限开发用」这种防旧教程误引的排除清单都写了 74 行。

**人物系统**（host-footage.md）把「真人出镜」做成了一个完整的输入规格：绿幕 mp4 或 alpha WebM 进，帧率必须等于成片 fps（不等时优先改成片 fps，「25 转 30 的简单重复帧让人物每秒卡 5 次，旁边原生帧率的动效丝般顺滑，对比之下更扎眼」）；全 CPU 抠像给了三种键控的实测排序，定版「绿优势度键」一条 ffmpeg 配方（公式到 despill 参数到羽化半径全写死）；人脸安全区用 `face_bbox.py`（OpenCV YuNet，模型 230KB）实测 bbox，「不目测、不用亮度阈值猜」，任何文字/卡片/字幕**及其背景**全时刻禁入。最有态度的是「人物与 B-roll 同屏」的处置：两者同在时**人物一律降级成角标常驻**——圆形头像章或抠人贴角，两路都必须落在画面下三分之一带内，「不许切走人（口播变配音 PPT）、不许人物占满画幅、不许角标里放静态头像」；角标期位置死锁，「让台的语义是我不抢戏，角标一动就前功尽弃」。

## 七、验收：五条机器闸 + 独立评审 + 三轮上限

这是我认为 talkcraft 比 shotcraft 走得最远的地方。七阶段流水线里的「三重验收」，关卡 1 是五条命令的机器闸，全 PASS 才进人工评审：

- `motion_check.py`：画面健康双判定。静止段用 ffmpeg freezedetect（阈值 0.8s，严于口径的 1s）；**并发光栅抖动**是第二次实战才确认的病——`--concurrency=4` 渲染时各 tab 光栅化亚像素相位不一致，静态文字区帧差呈严格周期 4 振荡（实测 1.4→3.1→4.0→0.9 循环），`remotion still` 单进程根本量不出来，必须量成片 mp4。所以交付渲染一律 `--concurrency=1`；
- `card_lint.py`：上面讲过的保真闸；
- `beat_lint.py`：词落点闸。每个画面重音落成 beats.json（`{t, anchor, sentence, what}`），**t 一律由 timing.json 查得，禁止手敲近似秒数**——「手敲曾把『啪、啪、啪』的画面做早 2 秒，静帧 QA 根本看不见」。闸校验每条 beat 与锚字首字词级 start 之差不大于 0.1s，外加镜尾保护带（动效落点距镜头出点须不小于 0.5s，否则会被转场吞掉——「第四条评论只活 0.2 秒」「停靠环只可辨 0.3 秒」是同类翻车的两案）；
- `sfx_check.py` 两查：**在场**（渲一条纯音效轨，每条 cue 在窗口内峰值不低于 −45dBFS 绝对阈值——旧版「高于底噪 12dB」的相对判法在数字静音的 solo 轨上任何非零音量都能过，「57/57 在场但全片听不见一记」是翻车实录）和**可听**（对最终混音跑：FFT 找人声延迟、最小二乘减去人声、残差按掩蔽分级 UNMASKED/AUDIBLE/MASKED；MASKED 超过一半、或 UNMASKED 少于 max(3, 片长除以 30 秒) 即 FAIL——「81/81 在场但全被人声掩蔽」也是实录）。

关卡 2 是独立 subagent 评审，「必须全新上下文，不许制作者自评」——而且 2026-08-30 把「独立」硬化了：**禁止 fork 制作对话当评审、禁止对同一评审做 followup 复审**，因为「fork 出来的评审继承制作者视角，对照物又是制作者自己写的 SHOTBOOK，形成自证闭环（P0/P1/P2 全零、成片却一身病）」。评审材料四件套里最有巧思的两件：**原版卡对比帧**（SHOTBOOK 用到的每个 slug 从画廊 mp4 抽 2 帧与成片对应帧并排，评审逐 slug 判「这是同一张卡的实现吗」——「保真不进评审视野就永远查不出来」）和**音效可听度报告**（「评审没有耳朵，机器报告就是它的耳朵」）。还有一组专门的材料设计，针对「只按句抽帧看不见的三类缺陷」：短命动效的错位给动效锚点定妆帧（每个重音加 0.25 秒），时域抖动给连拍三帧对，设计默默缺席给 SHOTBOOK 设计清单逐项「计划 vs 成片」核对。

缺陷分级有定义（P0 伤害理解 / P1 违反硬规则或明显走样 / P2 质感瑕疵记录不挡验收），返修有纪律（时间码三段闭环、状态型动画修复必须覆盖受影响区间并集、二次返工必须记录「第一次修复为何失效」、复核必须给量测数字——「首次可辨时刻/被吞时刻/占比像素」，「看起来好了」不算数）。最后是 2026-08-31 定版的**评审循环上限：3 轮**——3 轮后仍有未清的 P0/P1 就停手，把剩余缺陷清单、每轮修复记录和「为什么没修掉」原样交用户定夺，「无限自审自修不收敛，只会烧预算」。连可读性终检都是量化的：成片缩到 390px 宽（手机上刷到横屏片的实际宽度）复看，每行都要能读，「桌面全屏预览不是验收标准；排不下时先删次要文案，不缩字号」。

## 八、声音、字幕与设计语言：纪律的颗粒度

音效体系比 shotcraft 的「149 个 SFX 按片种选词汇表」更收敛：13 个合成音色 + 10 个真采样（直接内嵌自 video-shotcraft 的 Mixkit 库，base64 进仓库），逐卡 cue 表（共 188 记），全库定音后口味写得很清楚——「少而准」管的是同一时刻不叠双记、音量克制，**不是砍覆盖面**（主要动效入场全覆盖，对齐 demo 库密度，100 秒约 40–50 记）；ding 和 slam 两个音色全库清零（「不要收尾叮当、不要重砸」）；语义对位到具体采样名（打字 = 一记键盘采样 clip 盖住整段而非逐键梯子、画线 = 马克笔、弹出 = ui-pop）。两个口径的区分也交代了：demo 库音量上限 0.65 是试听口径，成片口径重新标到不大于 0.35、比人声低约 12dB。甚至 cue 的 file 名以 `ls public/sfx/` 为准这种 404 细节都写了。

字幕是这个 skill 里少见的「做减法」定版，两条铁律都来自用户：**素排**——底部跟读字幕不加任何动效，整句硬现整句硬走，唯一例外 keyword-pop-highlight 且全片最多 3 次（组件的 keywords prop 内建此上限自检）；**无标点**——句读全去掉，长句停顿靠拆卡，「问句情绪交给口播语气」，唯一例外是数字里的半角点号。

设计语言默认版是 Apple 范式：全片只有一个强调色（安静蓝）、全系统只有一个投影（只给证据素材，「卡片和文字永远不加投影」）、底色交替就是章节感、字重两档（400/600）。有意思的是它对「浅底」的两条量化红线：**转场白闪在浅底失效**（白底基线亮度约 237，叠白闪无处可涨——深底同表有 +29 亮度峰，浅底实测无峰，改做暗压闪）；**dim 件禁止再叠 opacity**（灰色在白底只有 4.29:1 对比余量，叠透明度实测掉到 2.06:1）。用户点名风格就整套 token 替换，唯一对任何风格都成立的硬约束是「禁止逐场景随手取色」。

## 九、和上一作放在一起看

把两作叠起来，系列的重心迁移很清楚。[video-shotcraft](/posts/video-shotcraft-skill-deep-dive/) 的护城河是**把隐性经验编码成 agent 可执行的规则**（配方卡、判例、流水线）；video-talkcraft 在这之上加的一层是**把规则的执行变成可测量的**。几条新的可迁移心得：

1. **凡是 agent 会自欺的地方，就上一个机器闸**。手敲秒数（「做早 2 秒静帧 QA 看不见」）→ beat_lint；凭理解重写卡片（「神似简化版」）→ card_lint 相似度；音效「在场」（相对判法骗过 57/57）→ 绝对阈值；并发渲染抖动（单帧量不出）→ 成片周期检测。每个闸背后都是一次真实翻车，翻车的共同点是「当时看起来对了」。
2. **验收材料的形态决定评审的上限**。三类单帧看不见的缺陷，配三种专门材料；原版卡对比帧让「保真」进评审视野；掩蔽报告给没有耳朵的评审当耳朵。给 subagent 的输入设计，本身就是给它的能力划边界。
3. **独立性要硬化到「禁止 fork」**。「派一个 subagent 评审」很容易做成形式——fork 出来的评审继承制作者视角，形成自证闭环。真正的独立是全新上下文 + 对照物不由制作者提供 + 每轮换新评审。
4. **自我修正要有界**。3 轮上限 + 剩余缺陷清单交用户，是对「无限自审自修不收敛」的承认。agent 的诚实不是「我一定能修好」，而是「我修不动了，这是清单」。
5. **输入边界是能力边界**。TTS、数字人、超分全部划出 skill 之外，配音是输入——skill 只做它有方法论优势的那一段。这个克制反而让全库的每一份文档都在同一层深度上。

还有个观察留给结尾：这个仓库只有 6 个 commit，但 SKILL.md 里沉淀着从 08-22 到 09-01 的几十条「定版」——每条都带日期、带用户原话、常常带一次具体翻车的帧号级描述（「第四条评论只活 0.2 秒」）。开发历史几乎不在 git 里，在规则里。上一篇我说 shotcraft 是「能自我供给训练数据的创作工具」；这一作把这个特性又推进了一步：**翻车本身被做成了基础设施**——每次「静帧 QA 骗过了我」的事故，最终都变成了一条机器闸、一张对比帧材料或一条量化口径。经验沉淀系统的下一步，大概就是这种「把教训编译成检查器」。

想上手的话：[在线画廊](https://vincentwei1021.github.io/video-talkcraft/) 78 条预览一页全览；`npx skills add Vincentwei1021/video-talkcraft` 或仓库链接直接丢给 agent 装好；然后给它「一份口播稿 + 一条配音」就能跑通全流程。两个提醒：工具许可是 PolyForm Noncommercial，商用需作者授权（做出来的视频归你）；以及它默认横屏 1920×1080，明确要发抖音才走竖屏版式——连画幅这种「开工先定」的事，它都在流程第零步写死了。
