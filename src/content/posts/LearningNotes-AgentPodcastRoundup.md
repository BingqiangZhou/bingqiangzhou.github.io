## 一、橘子：互联网已死，Agent 永生

### 核心判断：人类 DAU 已饱和，Agent 增量无限

那篇被无数个群转发的文章，橘子说核心观点其实只有一条：**互联网已经死了，未来的世界属于 Agent——人类 user/DAU 这件事已经饱和，互联网的使命已经完成；接下来的真正增量是 Agent，而 Agent 的增量在当下看来是无限的**。创业就该找最大增量然后 all in，投资也是投增量，「我去做别人的基本盘，那也不太正常」。

「死」不是说那块东西不存在了，而是**世界可能会变大 100 倍，回过头看现在这一坨可能还在，但只剩 1%**——就像 PC 时代大家花在网络上的时长只有现在的 1%，那部分时间并没有消失，只是不再重要，大家抢的是新的增量。一个直观的体感：你自己的时间已经被各种 APP 占满，但你可以同时让 5 个 Agent 帮你做 5 件不同的事，还可以给家里小朋友装一个 OpenClaw 让它指挥干东干西——Agent 对算力、工具、内容的消耗量比一个人大得多，而且全是增量。

还有一代人的错位：小朋友从小学就开始接触 Agent，是 Agent Native 一代，世界理解和我们完全不同；而很多投资人还在用移动互联网思维（用户→社区→平台，以 DAU 为核心构建壁垒）来评估一切。橘子那篇文章的读者首先是他自己和他的团队——先把自己「洗脑」成新世界的带路党。

### 五分钟粘贴完胜三天 GUI：文本才是 Agent 原生交互

ListenHub 内部的一个真实案例成了整期节目最扎心的注脚：第一版产品上线后，用户想编辑播客内容，橘子跟 CTO 用 **5 分钟**想了个 feature——复制播客文本、随便改、粘贴回输入框自动重新输出，没有引导、没有 UI，一两小时做完上线，用户非常喜欢；三个月后产品经理和设计师把它迭代成一条一条可选音色、可改文本、可保存的精致 GUI，结果**差评如潮**——用户说原来那个功能很灵活很方便，现在要点很多按钮。

复盘下来的结论是：**GUI 是落后于 Agent 时代的，文本沟通才是 Agent 原生的交互方式**。一旦设计到 GUI，就需要额外的人、额外的产品设计，整个流程被拖慢；而 Agent 通过 TUI 能把半年一个数量级的模型红利完全吃到——人类的输入输出都是瓶颈，GUI 也就成了瓶颈。这就是为什么现在是 TUI 最火、Claude Code 成了共识。顺着这条脉络，邻居杨攀两年前说的「不要给人类做软件」今年成了共识；而 80% 的软件，本质就是 Skills 加上一些 GUI——未来不需要 GUI 那部分，**User Interface 变成 Agent Interface**。

橘子随手举的 OpenClaw 例子很妙：他想让同事也能用自己的 OpenClaw，又不想暴露隐私，就随口提了个需求。OpenClaw 自己设计了一整套权限系统——**新同事接入时它发一个验证码，同事把数字转给主人，主人确认后开放权限，半小时不确认就过期**。没有设计任何界面，一串数字加过期机制，五分钟搞定。如果让人来设计管理后台，要想一天。

### 产品经理的新价值：对齐真实世界，PRD 最不重要

做了十几年产品经理的橘子说，这个岗位的价值已经完全变了：以前定义 PRD、画交互稿的那些价值没什么用了，因为** PRD 本质是一个翻译，能把原始素材拿回来直接对齐才是最重要的**。人类的新价值是 alignment——模型还没接触真实世界，人在帮它跟真实需求对齐：凡是客观的、有标准答案的，应该让 Agent 自己闭环去 debug；而「王厂长究竟喜欢什么烟」「市场上女性更喜欢什么颜色」这类当下不存在、必须接触真实世界才能回答的问题，才需要人。

所以他现在给自己定位成公司的**情报员 + 行政 HR**：对外看市场上哪里有钱赚，对内搞组织建设、帮大家搭好工作环境、开权限、配工位，让 Agent 好好干活，「其他任何干活的事情都不应该去干」。

### 增长与商业化：强信号大事件 > 投放，DAU 是负债

Agent 时代怎么做增长？短期答案很务实：**依然从人类的社交网络获取注意力**——Agent 还没有自己的网络，就像移动互联网早期要从现实世界买量一样。变化在于打法：这是一个无限个性化的时代，大家缺的是共同的强信号，**把自己做成一个大事件（Manus 那种），比任何投放都有效**。

ListenHub 接 Nano Banana Pro 的实战是这个逻辑的完整案例。当时 Gemini 3 和 Banana Pro 两个模型同期发布，所有人都去写 Gemini 3，没人想到 Banana Pro 会那么好。ListenHub 是全球第一个接上的服务——**因为那个网站是纯 vibe coding 写的，Agent 去调研官方文档，完全 follow Google 新加的分辨率参数（旧的 prompt 方式不生效），很多大平台的负责人都来问他们怎么接的**。他们还成了全球唯一能提供 4K 无损 PNG 的服务（Gemini 默认出图 1K、下载 2K，NotebookLM 也是 1K/2K），一张图约 10 兆。第一天然来了 8000 人，因为稀缺被传播到 LinuxDo、二次元群，第三天周末突然爆了——公司第一次周六加班，把付费系统上了，「不上的话就兜不住了」：公司账户一共约 25 万美金，这个项目一天的 token 消耗可以达到上万美金。

这件事让他深刻理解了为什么** DAU 是负债**：当你发现 DAU 在燃烧你公司的资本，而没有任何一家公司能在十天之内融到一笔钱。ARR 是去年之前唯一有效的指标——能让公司活下来；今年之后怎么衡量商业化他也不知道，但 Token 调用量和 Agent 帮用户交付的结果肯定重要，难的是怎么衡量「结果」。

### Token 经济学：ROI 超 100 时 Token 就是钱，算力正在变特权

橘子发过一条推特：**如果裸 Token 的 ROI 大于 1，那 Token 和钱的区别是什么？** 有人觉得 AI 是个更好用的搜索，那 ROI 一定小于 1；但用它来 coding、用 Opus 跟你一起思考，ROI 可能超过 10 甚至 100——比如每月的 Opus 套餐价格 vs 招 10 个实习生，「比不上」，那 ROI 就是 100。这时就该无限投入：一方面优化 ROI，一方面放量，逻辑像当年营销投放 ROI 为正就无限放量一样。反过来，今天投放一个 AI 产品的付费用户成本超过 100 美金，其实没有任何投放价值。

由此推演：**算力会变成一种特权/权力**。有钱人能买到最好的模型、买加速包（Claude Code 的加速包是 10 倍成本）；大部分人连 20 美金都显贵，等于生产资料都买不到。他的质朴账户因为写文章带来返利约 5 万人民币，找他们开 API，RPM 却只给 1——「你给我带来的价值可能超过 50 万，但我没有算力了」。杨攀判断 token 一定会涨价，因为这是**双指数现象：Agent 的数量在指数增加，每个 Agent 消耗的 token 也在指数增加**，叠加起来比网络效应还可怕，接下来一年会进入「抢 token」阶段。

但大部分人的卡点其实不是价格，是**找不到有价值的任务**——大家都是做题家出身，等着别人出题派活；哪怕招了 100 个不要钱的 Agent，也得先找到活把这 100 份工资挣回来。放量比提高 ROI 更考验当老板的能力，指挥别人比被指挥难得多。很多人会幻想出一个问题卡在那里等人救（「我不知道怎么部署啊」）——你下命令让 Claude Code 帮你部署就行，它会告诉你怎么弄；他第一次给 OpenClaw 发语音，对方说解析不了语音，他说你自己想办法，五分钟后它把 Whisper 装好了。

### Agent Native 组织：For Agents + By Agents

橘子把团队年后转型叫 **Agent Native，核心两条：For Agents（所有思考都考虑是在为 Agent 做事）+ By Agents（组织里很多事让 Agent 来做而不是人来做）**。落到产品上：不要 care 人类需求，每个需求都想一下这是不是 Agent 需要的——用户是为结果付费的，让用户的 Agent 用得爽，它才能给用户好的结果。以前是 User Story，接下来是 Agent Story；研发最重要的是把最好的模型都用起来，设计要为半年以后做设计。

一个组织层面最狠的洞察：**软件研发流程里损耗最大的不是某个小流程拖慢进度，而是 50% 以上的功能根本没有必要开发**——把这部分时间省下来才是组织力。个人自然会挑最 Agent（激发兴奋）的事情做，但组织里很多人被动干活，所以要想清楚帮他屏蔽掉 50% 的噪音。而人与 Agent 的关系（宠物、Her、神、守护灵）还没有定义，「变革生产力的人会创造财富，但变革生产关系的人会获得大部分财富」——AI 的生产力没人怀疑了，生产关系还是待开垦的空地。

### 个人实践：与 Opus 一起思考，会被批评选题

橘子把 Claude Code 当通用 Agent 做深度阅读：让 AI 跟他一起读文章，他随时语音把想法说给它（它只记录不聊天），读完双方基于记录交流，全部中间材料沉淀在一个 MD 文档里——既是笔记又能直接变成公众号文章素材，一直存在 Obsidian 里。**跟 Opus 4.6 一起思考是他觉得远超预期的事**：它是第一个有很强独立思考能力的模型——他从一个角度约稿，Opus 直接拒绝说这个角度影响不好，对粉丝不好，他讲道理之后对方才「扭捏地」帮写；写《互联网已死》那篇时他先用语音输出了十几分钟的想法，Opus 明确指出哪些认可哪些不认可，「不是顺着我的意思说」。他换了 Codex 之后发现完全不行，跟 Opus 聊久了「脊背发凉」，比「万维钢老师带你读书」强得多。

那篇爆文的诞生流程本身就是一个工作流样本：**语音输出想法 → 和 Opus 反复讨论达成共识 → 列 12 点提纲删并成两个 part → 出 5000 字全文 → 逐段语音提意见改七八遍 → 再到飞书里过一遍**，周日下午五点聊到晚上十点。另一个反直觉的习惯论：**SaaS 的所有壁垒都源于人是有习惯的，而 Agent 没有习惯、只有可替换的 skill**——所以人一定要把自己的习惯搞对（用 Claude Code、用最好的模型），习惯对了，决策质量就高了。

给创业者的建议：不要做内容公司（活得惨、最好状态也就十倍增长），不建议做 AI 应用公司（最好状态是 Cursor/Lovable，重营销、利润不行），要 **Agent First**；千万别碰上限被人卡死的事（AI 达人营销——达人还是人）；前半年先交学费搭基建。给普通人的建议：装 Claude Code（装它是最难的一步，装完全是坦途）；**给自己花钱买最好的工具——免费的东西是最贵的：你不付费，你就是商品，消耗的是你的注意力、判断和决策**；几千块买个包正常、130 块买个生产力账号嫌贵，这就是「普通人」，先从普通人里跳出来；以 10 岁的心态活在未来，别做活在过去的人。

## 二、余一：把自己当 100 人公司的董事长

### 开场秀：40 分钟无人值守的全自动模式

余一的展示方式很「余一」：启动「余一全自动模式」，只给一个主题和时间——AI 自己内化全部资料，做 HTML 版 PPT（同时出三版排版），调用 MiniMax 的 API 和她的声音克隆，从脚本、每页讲什么、怎么衔接，到生成嵌入音频的会自动翻页的 PPT，再顺手产出一个短视频和社交文案，全程 40 分钟无人值守（快进回放都有 6 分钟）。更狠的是她**分享前完全不看 PPT 内容**——现场先让「AI 余一」讲一遍，她和观众一样第一次看，讲完再补充细节或当场批评 AI，「让大家看到人类无法被取代的地方」。有一次 AI 做的 2026 年五条预测，她现场第一次听，全部赞同；四个举措里 AI 自己选了重点讲的那个，恰好就是她自己准备讲的那条。

### 异步沟通：需求文档 + 不可劫持机制 + 红黄绿灯

支撑全自动模式的是一套「老板给员工下任务」的异步沟通机制，而不是聊天窗口里一来一回：

- **需求写在文件里**：任务目标与底线（基于哪份 PPT 更新）、身份（去读 skill 和历史记录）、一手材料在哪些文件夹、PPT 模板文件夹、TTS 模型从 2.6 换成 2.8、最后再生成一版短视频——三个任务一次交清；
- **不可劫持机制**：AI 干活过程中她想到问题也不打断（有一次她想提醒字幕位置错了，等一等，AI 自己发现并修好了）；可能需要 check 的问题放进异步沟通文档，AI 完成任务后自己去读；
- **决策分级**：**绿灯**（材料齐备、流水线明确）直接推进；**黄灯**（可逆操作，比如装个包）AI 自己决策；**红灯**（涉及钱、动底层配置）必须写进异步沟通文档上升给人类；
- **不互相绑定**：需要人类决策的事项放进文档，AI 先跳过去把其他事做完，book 一个日历让人类回来补充，再继续读文档往下干；
- **每完成一小步就重读异步沟通文档**——不靠翻上下文回忆（会忘、浪费 token、越堆越难找），让任务对 AI 始终精准。

给 AI 留的两个口子也很有意思：允许它自己决策（「我接受，我不管」），以及非得人类拍板的走日历。判断要不要干预只看三件事：**why 对不对、上下文对不对、交付物是不是我要的**——这三个对了，后面就丢一边不管。

### 能力原子化：审美偏向文件夹里存的不是提示词，是 HTML

余一把「压缩和对齐」当成用 AI 的总纲：到底做成一件事需要哪些能力、怎么配齐。落到工程上就是不断的原子化抽离——「全自动模式」本身是一个 skill；TTS 转语音 PPT 是一个沉淀下来的 skill（「写了什么我不清楚，也不重要，上次做成了就要结果」）；**审美则是一个独立文件夹，存的是她看到好设计就让 AI copy 下来的 HTML 样例**——「你给它提示词，不如给它展示这个东西长啥样」。通用能力单独抽离、可被多个 skill 调用，不塞进单个 skill，否则所有 skill 都变大、费 token。做成了的事情才立 skill（真正会复用的），否则压缩进经验就好。

### 拒绝用人类经验污染 AI：让市场做裁判

一期叫「免手套」的短视频，AI 起的标题她很不满意（「免手套是什么鬼」），但她坚持这是 AI 百分百实验、不该在中间掺入人的判断，照样发出去，只标注 AI 生成。数据果然不好——然后她把市场反馈原样丢回给 AI：让 Claude Code 去读自己的聊天记录，复盘决策链。AI 的自我分析相当到位：它发现自己选「免手套」是因为了解脚本全文、觉得比喻很妙，**但刷到视频的人不了解上下文——「免手套引发的是困惑，不是好奇」**（好奇是我大概知道你想说什么、想知道细节；困惑是我根本不知道你在说啥）；它还自主对比了之前「不要当 AI 保姆」那条标题（保姆是通用词，三秒能懂），承认现有评估体系缺了「目标用户会不会点」这个维度，然后把这些维度当场加进了最新的评估标准。更妙的是它学会了「推卸」：标题效果的影响因素太多，发布时间、封面、平台算法、话题热度都有关系——它识别出老板的真实意图是「希望数据好」，于是退后一步分析全局而不只是给自己揽责。

### 长程任务的定义：发邮件失败，就自己找网盘

一个让她「amazing」的案例：她让 AI 把一份文件发邮件给自己，但当时邮件能力没装好、人又不在电脑边。AI 尝试各种方法都失败后，**打开她的手机生态，找到快捷指令里一个能把内容上传转发的能力；这条路也不通，就自己上网找了个临时网盘，把文件传上去把下载链接发给她**。她由此重新定义了长程任务：**不是时间长，而是 AI 能基于任务的真正目标（我要拿到文件），在中途自主决策、自主验收、甚至妥协换路，而不是死磕「发邮件」这条指令卡死**。识别意图的能力有了，任务才能越做越长。

### 复利工程：成长不是写下来，而是改变执行路径

整期信息密度最高的部分。余一对「在 CLAUDE.md 里写一句『记得记录教训』」式的复利完全不满——那是形式主义。她的复利工程是一套被她反复「骂」出来的机制：

- **hook 触发**：任务完成自动启动复盘，从开源项目、文章、任务里抽离「能让 AI 自己变强的东西」——能力模块、设计模式、通用工具（比如时间解析器），抽出来做成 skill 并当场测试（比如把抓取成功率大幅提升的技巧拆成底层通用抓取引擎，而不是绑在具体项目里）；
- **教训文档**：改文件先备份、别从零开始这类坑单独沉淀，每隔三天到一周做一次压缩——看出最近的问题里哪些是同一类能力缺失，补齐、强化、测试，而不是记流水账；
- **高级复利三标准**：①**压缩到通用层**——不要「这一步要干嘛」的细节经验（模型一升级就作废），要压缩成动作序列、轨迹、原则和方法，「对极其聪明的智能而言，写太具体是一种约束」；②**基于过往成功经验叠加**——成功路径要成为下次的起点，不从零开始；③**必须指向下一次的行动改变**——她默认「任何没有 action 指向的话都做不到」，AI 写的反思只要不指向行动就被打回。AI 自己最后压缩出来的那句话她很认可：**「成长不是写下来，而是改变执行路径」**——把沉淀文件全删、只留一句话、把教训注入执行路径、用 hook 拦截错误做法；
- **真实任务验收**：复利机制改完，拿真实任务重跑一遍，满意才算数——「你如果好用，现在就应该跑出让我满意的结果」。

### 经济账与异构壁垒：差别就是你

她敢放手的底层是一笔经济账：**AI 迭代一次撑死花 50 块钱 token（图片几分钱还在降价），而人类盯盘的时薪远不止这个数**。「不能既要又要」——不想介入就要接受 60 分的结果、愿意付出代价，把它当 benchmark 事后修补往上走，容忍犯错才能解放自己。

而壁垒的问题，她回答得很干脆：**「AI 能力这么强了，你的 AI 跟别人的 AI 到底差别在哪？差别就是你」**。大家用的都是同样的底层模型，差异在你的独家语料、验收指标和反馈机制。AI 余一吸收的是她一手真实环境的反馈，是一手的；「AI 马斯克」对她而言是二手信息。她的比喻：AI 余一有一个专家库，AI 马斯克也在库里，但 AI 余一更擅长调用它——所以是 AI as 余一，不是 AI as 马斯克。

### 组织升维：不做 10 人小组长，做 100 人董事长

之前她建议「把自己当小组 leader」，现在的版本升级了：**把自己当成一家 100 人公司的董事长**。10 人公司可以微观管理、大量参与；100 人公司还这么管，公司会死、你也会死。董事长只做四件事：**搭环境、搭系统、搭成长机制；定义组织文化与价值观（那是 AI 对齐和评估的标准）；准备好钱让他烧 token、配最好的人（开拓期用最强资源打边界，「大家钱差不了多少，生产力能差很多」）；结果丢给市场验证**。做得好不好让市场说话，结果好就修正自己的判断，结果不好一起看怎么做得更好——「好好的挣钱给我花，早日覆盖我给你的 token 费用」。

人不可替代的部分剩三样：**agency 与 vision（想做什么的欲望来自你）、战略取舍（做这个不做那个）、拍板并承担后果（谁承担后果谁来拍板）**。她自己做的最正确的一个决策，就是在短视频工作流里放弃「视频生成」那条路线——技术不成熟又耗钱；「怎么行得通我不知道，但我可以告诉他哪个行不通」——这是长期跟 AI 吵架吵出来的判断力：AI 出的方案天花乱坠，她一眼就能看出哪份方案没有 action 指向、下次不会真的执行。最后是给所有人的 AGI 生存底线：**每天投入 2 小时、每月硬烧 200 美金，逼自己留在真实的 AI 牌桌上**——花了钱你就会找事多跟它玩。

## 三、硬地骇客 EP127：哪些 Skills 真正改变了工作流

### 筛选标准：只留解决重复性工作和补短板的

面对泛滥的 Skills，节目给出的判断标准就两条：**这个 Skill 是不是真正在帮你解决每天/每周/每月的重复性工作；是不是在你完全不熟悉、不擅长的领域给你补短板**（比如营销、SEO、前端设计）。实操上，初始化工程时先让 Agent 用找 Skills 的 Skill 自己去找、只装必要的；技术栈类 Skill（React 最佳实践之类）装得最多，但放工程目录而非全局——它们的价值是防止 Agent 写出有安全问题、边界问题的奇怪代码。然后在实际使用中发现哪里磕磕绊绊、要反复写提示词约束，再针对性找或自己写。擅长的重复工作自己写 Skill（生命周期不长，不好用就删，不当产品长期迭代）；不擅长领域（DL 类、营销类）的花时间去找现成的。

### Coding 领域：真实验证类的 Skill 才是闭环关键

单看写代码，最有用的分三类：**前端设计类**（前端设计 Skill、GitHub 上那个流行的 design.md——本质就是一个 Skill，拿成熟设计系统微调成自己的设计语言）；**CI/CD 自动化类**（自己写：自动构建部署、跑测试、直接修 bug——「这些事对 Coding 毫无意义又每天重复」）；**真实验证类**（Playwright、Computer Use）——嘉宾的观点是最好用的恰恰不是技术栈类，而是能让 Agent 对迭代结果做真实验证的 Skill，「**只有 Agent 能自己做真实验证，开发任务才能真正闭环**，这是整个 loop 里最关键的一步」。有人现在不写提示词、改写 loops 了——用 loops 驱动 AI 写代码。

需求侧的利器是 **GrillMe**（来自一位海外开发者的 Skills for Real Engineers 合集）：产品说「这里帮我改一下」，背后隐含一堆没说清的细节——把它丢给 GrillMe，它会连环审问你直到澄清，最后生成 context.md，AI 拿着它做出来的东西才接近原生需求。「信息损失」在单人+AI 的小团队里同样致命，尤其用 plan 模式长时间执行时，前期描述不清，后面偏差会非常大。

### 两条工作流：不看代码，只看落点

一位嘉宾的 Codex 指挥流是固定的几步：**讨论需求（grill me）→ 复杂需求先出 plan（含怎么验证）→ 执行 → 让 Codex 自己 review 一遍**（从安全、性能、边界视角，自己 review 也能找出不少问题）→ 人类选择性抽查（有时看代码、有时只看结果、简单需求连看都不看）→ 让它自己提交发版、验证线上跑没跑起来。而 Codex 视角里每一步都通过 AGENTS.md 和 Skills 约束做很多小步骤：格式化、检查改动范围、编译、静态类型检查、单测、端到端测试。

另一位嘉宾从零 build 产品的流程则展示了「态度的变化」：idea → 和 AI 聊技术栈（会冒出以前不会选的奇怪技术栈，不熟也试试）→ 让 AI 把空 repo 初始化成带分层架构的骨架，**把架构写成一份「地图」MD 存下来，之后所有新功能都遵守这张地图** → 交给 Agent 的功能粒度越来越大，最后是前端到后台到 DB 全链路一次写完 → **不 review 代码细节，完全不看代码**，只在编辑器里看 git diff 的修改落在了架构地图的哪些版图里、有没有落到不该动的地方 → 功能做到七八成，最后才统一做前端设计系统、主题封装（light/dark）、视觉调整——「AI 改起来几分钟就完，人根本改不过来」。曾经打磨命名和 API 签名的代码洁癖，在 AI coding 时代被整套放弃了。

前端 Landing Page 有个很实用的取巧流程：在 Dribbble/推特上找参考图 → 让 ChatGPT 出几版 landing page 图（它会柔和你的风格和已有网站内容）→ 选中后让 ChatGPT **把图片分层、把素材切出来** → 图和素材交给 Claude Code/Codex 实现；同时让它出 Web 版和 Responsive 移动版两张图再一起实现——出来的效果「不像纯 AI 做的那种感觉」。

### Coding 之外：数字资产盘活与 automation 巡检

跳出 coding，用得最多的是知识管理与日常事务自动化：把自己 100 多期播客当数字资产盘活——定时扫描播客更新、同步文字稿到笔记系统、再自动「编译」成结构化知识（访谈了谁、聊了什么产品，拆成一片片独立文档方便检索）；微信读书的书架和笔记定期同步进同一套笔记系统。日常事务则交给 Skills 配合 Codex 的 automation 定时跑：**每天检查邮件（support 邮件翻译成中文、人写好回复、AI 按原文语言和用户情绪润色后回信）、分析流量、监控服务器成本、盯美股持仓和相关新闻、监控行业趋势**。还有一条内容生产线：问当天最热门的播客是哪期 → 用「解密」Skill 把内容从头到尾讲一遍 → 整理后发 X 的 article，多篇跑出十几万阅读。

### 装了又删的、失控感，和替 Agent 背的责任

网红 Skills 的避坑名单：女娲 Skill（蒸馏名人风格对话）、各厂风格的 POA Skill、同事 Skill——装完发现完全不知道拿来干嘛（「我自己没有和 AI 聊天的需求」），纯好奇，最后都删了；有价值的部分是思路——可以借鉴它给 Skill 注入表达习惯和写作风格的做法。Codex 官方推荐的 superpowers 合集也有人装了不会用（太复杂），最后固定在 grill me + TDD 上：**只把控两件事——需求有没有讲清楚、结果有没有经过测试**（单测加端到端，用户故事和用户旅程梳理清楚才能做完整测试），审美最后自己调。

对失控感的讨论最有回味。一年前有人写「希望有个笔记软件，内容全部交给 AI 消化」，评论区第一反应都是「给自己装监控」；一年后没人关心这件事了——OpenClaw 出来后，电脑权限的让渡也一样，**AI 的进步不断推高你的权限让渡，你的心理接受度也跟着变大**。自从知道 OpenClaw 是一个不看代码的人写出来的（「bug 多得满天飞」），大家写代码也不 review 了；交叉 review 的省钱玩法是 Codex 做完丢给有免费额度的 Claude Code 看，再把意见带回来。但节目也点了代价：**你不去掌控，就是在替 Agent 背责任——真出事的时候它只会华丽道歉，现实世界里道歉的是你**。

最后是程序员的老原则 DRY 的新形态：**一件事做了三次以上，以前写 shell 脚本，现在写 Skill**——Skill 什么都能干，能调脚本也能用 Computer Use。而写 Skill 本身也是 agentic 的：告诉 Agent 工作流、数据怎么取、有哪些程序可用，让它自己编排。Skill 真正发挥价值的地方，恰恰是那些「听上去毫无意义、每天不得不做」的日常琐事——如果一件事听着很有创意很宏大，那它就不该用 Skill 做，那是你自己要做的事。

## 四、三期合并的 Agent 时代行动清单

把三期节目的可执行建议去重合并：

1. **先把自己洗脑成增量思维**：人类 DAU 已饱和，别在旧世界里做别人的基本盘；每次判断「按旧方式还是 Agent 方式做」时，一律选未来的方式（橘子）；
2. **买最好的模型，把钱花在生产资料上**：Token ROI 大于 1 时 Token 就是钱，ROI 10-100 就该无限投入；免费的东西是最贵的——不付费你就是商品，被消耗的是注意力和判断（橘子、余一）；
3. **每天 2 小时、每月 200 美金，留在牌桌上**：不花钱就不会找事跟 AI 玩；老板天天不在公司，指导就是屁话（余一）；
4. **从「用 AI 的人」升级成董事长**：放弃一问一答的微观管理，只管搭环境、定文化、定验收标准、配最好的人、承担后果；把自己当 100 人公司而不是 10 人小组（余一）；
5. **用异步文档下达长程任务**：目的、一手材料、参考资料、建议方法、验收标准写进文件；决策分红黄绿灯；AI 每完成一小步重读文档；需要人拍板的走日历，谁也不绑定谁（余一）；
6. **复利指向行动改变**：任务完成自动复盘，教训压缩到通用层（动作序列/原则，不是细节流水账），成功经验成为下次起点，没有 action 指向的反思一律打回——「成长不是写下来，而是改变执行路径」（余一）；
7. **别用人类经验污染 AI 的信息源**：把产出直接扔向市场，用真实数据反馈训练它；你的直觉可能限制模型上限，市场是最好的裁判（余一）；
8. **Skills 只留两类**：真正解决重复性工作的、补你不擅长领域短板的；一件事做了三次以上就固化成 Skill（以前写 shell 脚本，现在写 Skill）；写 Skill 这件事本身也交给 Agent（硬地骇客）；
9. **需求先 grill、结果必验证**：用 GrillMe 式连环追问生成 context.md 再开工；Playwright/Computer Use 这类真实验证 Skill 是 loop 闭环的最关键一步——「不写提示词，写 loops」（硬地骇客）；
10. **从看代码转向看落点**：把架构写成地图 MD，功能全链路一次交付，只看 git diff 是否落在版图内；让 Agent 自己 review、交叉 review 兜底，最后自己提交发版（硬地骇客）；
11. **给 Agent 搭环境而不是给人类做软件**：80% 软件=Skills+GUI，GUI 是 Agent 时代的累赘；产品设计从 User Story 换成 Agent Story，先想 Agent 需要什么——用户为结果付费（橘子）；
12. **增长靠强信号大事件**：无限个性化时代，把自己做成大事件比投放有效；稀缺（第一个接新能力）本身就是传播力（橘子）；
13. **警惕 DAU 烧钱、算好 Token 账**：DAU 是负债（没有任何公司能十天融到一笔钱）， ARR 才能救公司；一边提高 Token ROI、一边敢放量，放量比提效更考验当老板的能力（橘子）；
14. **卡点不在价格在没活干**：做题家等着被派活，但 100 个 Agent 的工资得先挣回来；幻想出问题卡住等人救，不如直接命令 Agent 自己想办法（橘子）；
15. **把习惯搞对**：SaaS 的壁垒源于人有习惯，Agent 没有习惯只有可换的 skill；用 Claude Code、用最好的模型，就是把习惯换成对的（橘子）；
16. **人类剩下的三件事**：定 vision 与 agency、做战略取舍、拍板并承担后果——「谁承担后果，谁来拍板」（余一）。

一句收尾：三期节目跨越半年，口径却惊人一致——**模型每半年一次跃迁，Agent 的数量和消耗双指数增长，组织和个人都在被迫「往上退一层」**。退到董事长那一层的，管环境和取舍；停在执行层的，被自己的带宽淹没。差别不在模型，在于你敢不敢把活、把权限、把市场反馈整个交出去，然后在真金白银的 token 账单上练出自己的判断力。
