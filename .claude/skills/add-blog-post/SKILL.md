将外部 Markdown 笔记批量导入当前 Astro 博客仓库的标准化流程。

## 前置准备：了解博客规范

在动手之前，先扫描仓库获取以下信息（这些是自动从代码中推导的，不要问用户）：

1. **文章目录**：找到存放 `.md` 文章的目录（通常是 `src/content/posts/`）
2. **Frontmatter schema**：读取 `src/content.config.ts`（或类似的内容配置文件），了解必填和可选字段
3. **现有命名规则**：列出已有文章文件名，归纳命名模式（如 `Category-TopicPascalCase.md`）
4. **标题格式**：检查已有文章的 `title` 字段格式（如 `【标签】描述`）
5. **已有标签列表**：提取所有已使用的 `tags` 值，归类整理

这些信息决定了后续所有步骤的格式要求。

### 标签分类参考

根据文章**核心内容**选择标签，而不是按主题领域归类：

| 标签 | 适用场景 | 典型内容 |
|---|---|---|
| **学习笔记** | 系统**学习**某个知识领域，侧重原理讲解和知识梳理 | 概念总结、技术原理、读书/课程笔记 |
| **实践记录** | 记录一次具体的**动手操作**过程，侧重步骤和遇到的问题 | 环境搭建、配置过程、踩坑记录、问题排查 |
| **工具分享** | 介绍某个**工具/服务**的使用方法和推荐理由 | 软件推荐、平台对比、API 使用指南 |
| **碎碎念** | 随想、感慨、非技术性短文 | 个人感悟、博客动态 |
| **论文阅读笔记** | 阅读**学术论文**后的整理总结 | 论文方法解析、实验分析 |
| **读书笔记** | 阅读**书籍**后的整理总结 | 书籍章节梳理、读后感 |

**判断优先级**：实践记录 > 学习笔记 > 工具分享。即：如果文章既有工具介绍又有实操步骤，优先选"实践记录"；如果既有知识梳理又涉及工具，优先选"学习笔记"。只有文章核心是"推荐/介绍某个工具"时才选"工具分享"。

## 执行流程

### 第一步：复制文件

将源 Markdown 文件直接复制到文章目录，不要做任何内容修改。

### 第二步：添加 Frontmatter

为每个文件添加 frontmatter 头部，规则：

- **title**：遵循已有标题格式（如 `【标签】描述`），从正文 H1 提取并按规则包装
- **published**：使用当天日期，格式 `YYYY-MM-DD`
- **description**：从正文内容提炼一句话摘要
- **lang**：根据文章语言设置（中文文章填 `zh`）
- **tags**：从已有标签列表中选择最匹配的，可多选

同时**删除正文中的 H1 标题行**（`# 标题`），因为 frontmatter 的 `title` 会负责渲染页面标题。保留 H1 下方的引用块（`>`）、正文等内容。

### 第三步：重命名文件

按已有命名规则重命名文件，常见模式：
- 英文 PascalCase，无空格无中文
- `CategoryPrefix-TopicName.md` 格式
- 与同类别已有文件保持前缀一致

### 第四步：确认与预览

向用户展示每个文件的：
- 文件名（新旧对比）
- frontmatter 内容
- 标签选择

然后启动开发服务器预览效果。

## 内容清理与修复

在添加 frontmatter 之后、重命名之前，扫描正文并修复以下常见问题：

### 时间戳链接格式

笔记软件（如 Obsidian）导出的时间戳链接常见格式为 `[[00:02](url)]`，需要修复为标准 Markdown 链接：

- **问题 1**：外层多了一对 `[]`，写成 `[00:02](url)`。`[[` 会被部分解析器当作 Wiki 链接语法，导致渲染异常。
- **问题 2**：`[00:02](url)` 中冒号被 Markdown 解析器截断，实际渲染为 `00`（丢失 `:02` 部分）。

**正确写法**：用反引号包裹时间戳文本 `` [`00:02`](url) ``，确保完整渲染。

**批量替换规则**：

```
[[00:02](url)]  →  [`00:02`](url)     # 原始格式 → 修复后
```

即：去掉外层 `[]`，在内层链接文本 `[...]` 中用反引号包裹含冒号的时间戳。

### 空行分隔检查

正文中的时间戳行（以 `` [` `` 开头）彼此之间必须有空行分隔，否则 Markdown 会将相邻行渲染为同一段落。检查所有时间戳行，若相邻两行之间没有空行，插入一个空行。

### 标题层级检查

检查正文中 `#` 标题的层级是否合理：

- **不允许 H1**：正文中不应出现 `# 标题`，因为 frontmatter 的 `title` 负责渲染页面标题。
- **层级不跳级**：`##` → `###` → `####` 应逐级递减，不应出现 `##` 直接跳到 `####` 的情况（如 `##` 下没有 `###` 就直接用 `####`）。
- **同级标题保持一致**：同一层级的标题应使用相同数量的 `#`。

如果发现层级问题，按上下文语义调整 `#` 数量。

### 分隔线检查

检查正文中的 `---` 水平分隔线使用是否合理：

- **只保留 H2 前的分隔线**：`---` 可以出现在 `##` 二级标题前，作为章节间的视觉分隔。
- **删除 H3 及更低级别标题前的分隔线**：`###`、`####` 等标题前不应有 `---`，避免页面中出现过多水平线。
- **删除末尾的分隔线**：正文末尾如果没有紧跟标题，`---` 也应删除。

### 其他内容清理

- 如果正文中包含手动目录（`## 目录` 及其下方的链接列表），将其**注释掉**（用 `<!-- -->` 包裹），因为博客主题会自动生成目录，手动目录是冗余的。同时检查目录前后是否紧邻 `---` 分隔线，如果有，将分隔线一并纳入注释范围，避免在正文中残留多余的水平分割线。

## 注意事项

- 标签必须从已有列表中选取，不要随意创造新标签。如果觉得需要新标签，先询问用户
- 文件名只用英文字母、数字和连字符
- frontmatter 日期不要带时间部分，与已有文章保持一致（`YYYY-MM-DD`）
- 如果用户提供了多个文件，并行处理但统一展示结果
- 如果用户对标签、标题、文件名有修改意见，立即调整不要重新走完整流程
